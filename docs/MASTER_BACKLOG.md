## Scoring and hard gates

`Score = (Business Impact × User Value × Traffic Potential × Strategic Leverage × Confidence) / Effort`

Business impact, user value, traffic potential, strategic leverage, and effort use 1–5. Confidence is 0.50, 0.75, or 1.00. Higher is better; effort is the denominator.

Hard safety, scientific correctness, provenance, publication integrity, accessibility, production incidents, dependency ownership, review blockers, and exact-head validation override numeric score.

### Backlog hygiene rules

- GitHub state outranks stale prose.
- One normal owner per D/R/A workstream; L1–L5 do not create additional slots.
- An open stacked/dependent PR is recorded but does not create capacity.
- Research-only staging is not implementation and cannot create scientific/source authority.
- Any temporary control/incident overflow is explicit and freezes **new** admission until reconciled.
- A merged/closed item may appear only in history/retired sections, never `Now`.
- An open PR that already owns a problem outranks creating a duplicate ticket.
- Stale external assumptions lower Confidence or require revalidation before promotion.
- Missing production/external observations remain `Unknown`, never zero or inferred success.
- Safety/scientific/provenance/accessibility incidents may override score and ordinary lane order.
- No broad auto-publishing or scientific rollup is authorized merely because tooling exists.
