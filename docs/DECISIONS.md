## 2026-08-21 — Control-document authority

**Decision:** `PROJECT_CHARTER.md` defines boundaries; `CURRENT_STATE.md` describes implementation reality; `ROADMAP.md` defines milestone direction; `CURRENT_SPRINT.md` is the only immediate queue; `MASTER_BACKLOG.md` holds ranked future work; this log records durable choices; `SCOREBOARD.md` owns metric definitions and values. Code, configuration, tests, deployment behavior, and reproducible audits outrank descriptive documentation when they conflict.

**Rationale:** The repository contained several contradictory status, strategy, and backlog systems.

**Alternatives considered:** Keep all planning files co-authoritative; delete historical files. Both either preserve ambiguity or destroy useful history.

**Consequences:** Older plans are reference/legacy material unless promoted through this system. **Status:** Accepted.

## 2026-08-21 — Stable URL policy

**Decision:** Preserve `/herbs/:slug`, `/compounds/:slug`, `/guides/:cluster/:slug`, `/learn/:slug`, `/info/:slug`, and `/evidence/:slug`. Treat currently active `/articles/*` and `/goals/*` as user-facing compatibility surfaces until traffic and canonical evidence supports consolidation. Every rename/removal requires a redirect, internal-link update, sitemap/canonical validation, and regression test.

**Rationale:** URLs carry user value and search equity; live evidence shows some nominally legacy families remain active.

**Alternatives considered:** Bulk migration to the newest taxonomy. Rejected without demand and redirect proof.

**Consequences:** Consolidation is route-specific, not a cleanup sweep. **Status:** Accepted.

## 2026-08-21 — Source-of-truth and generated data

**Decision:** `data-sources/herb_monograph_master.xlsx` is the primary structured authoring source for broad herb/compound changes. `public/data/` is a core publish target generated by `npm run data:build`; narrow reviewed patches may touch generated JSON only when documented. The post-invariant publication artifact—not a pre-build overlay—must become the authority for final robots/sitemap eligibility.

**Rationale:** Current manifests and pipeline phases report contradictory eligibility counts.

**Alternatives considered:** Replace the workbook pipeline or edit all JSON directly. Rejected because the pipeline is working and entrenched; observability should be repaired first.

**Consequences:** Generated changes require validation and a production build. Stale `publication-index.json` and empty `source-registry.json` cannot be treated as current truth. **Status:** Accepted; implemented by SEO-001 in PR #4262, with the final report remaining verification evidence rather than a publication input.

## 2026-08-21 — Generated-content rules

**Decision:** Automation may propose or assemble content, but publication requires unique user intent, validated fields/slugs, traceable sources, evidence-role review, safety coverage, and human review proportional to risk. Automation must abstain rather than fill unknowns. No mass content generation is authorized by a page-count goal.

**Rationale:** Scale amplifies evidence and duplication errors.

**Consequences:** Programmatic expansion remains Later until the decision-page engine is proven. **Status:** Accepted.

## 2026-08-21 — Evidence release gate

**Decision:** Decision pages must follow `docs/content-quality/evidence-first-decision-page-standard.md`. Mechanism, observational, preclinical, adjacent-population, null, conflicting, and funding evidence must be represented honestly. Trial doses/timelines are context. Robots must not be manually relaxed to bypass missing evidence roles.

**Rationale:** Trust and directness are the product's core value and a safety boundary.

**Consequences:** Evidence gaps may hold a page from indexing or ranking claims. **Status:** Accepted.

## 2026-08-21 — Safety release gate

**Decision:** Preserve structured warnings, contraindications, interaction context, population limitations, and escalation guidance. A runtime/source safety-contract mismatch blocks release for the affected page. Revenue or traffic potential cannot override this gate.

**Rationale:** Supplement decisions can cause harm and require conservative uncertainty handling.

**Consequences:** Safety defects are P0/P1 regardless of commercial score. **Status:** Accepted.

## 2026-08-21 — Work-in-progress limit and execution rule

**Decision:** Maximum three concurrent workstreams: Discovery/SEO, Revenue/Conversion, and Authority/Content. Within a workstream, activate one ticket at a time; each agent owns one scoped ticket and stops after proof and record updates.

**Rationale:** The open queue and overlapping PRs create merge drift and unclear completion.

**Consequences:** New work waits unless an active ticket is completed, blocked, or explicitly displaced. **Status:** Accepted.

## 2026-08-21 — Backlog prioritization

**Decision:** Score eligible tickets as `(Business Impact × User Value × Traffic Potential × Strategic Leverage × Confidence) / Effort`. Impact/value/traffic/leverage and effort use 1–5; confidence uses 0.50, 0.75, or 1.00. Scores order comparable work but do not override dependencies or evidence/safety gates.

**Rationale:** The model is transparent, compact, and penalizes costly or weakly supported work.

**Alternatives considered:** Revenue-only ranking and an unscored task list. Both hide trust, user, dependency, or confidence costs.

**Consequences:** Any task that weakens safety, evidence, disclosure, or trust is ineligible regardless of score. **Status:** Accepted.

## 2026-08-21 — Monetization and affiliate disclosure

**Decision:** Evidence order and recommendations are independent of commission. Disclose the affiliate relationship clearly before or with the first commercial link; use centralized tags; mark paid links appropriately; validate destinations and material product/form differences. Broad comparisons must not monetize only one ranked option without an explicit editorial reason.

**Rationale:** Commercial transparency protects users and long-term trust.

**Consequences:** Missing disclosure or misleading destination blocks a commercial-page release. **Status:** Accepted.

## 2026-08-21 — Infrastructure-change threshold

**Decision:** Modify or replace infrastructure only when evidence shows it is broken, blocks indexing/users/revenue/safety, prevents reliable agent execution, or prevents trustworthy measurement. Prefer the smallest extension or repair.

**Rationale:** The current system is complex but deployed; speculative rewrites delay the growth loop and introduce risk.

**Consequences:** Architecture work needs a scoped ticket naming the blocker and rollback/proof plan. **Status:** Accepted.

## 2026-08-21 — Existing-page upgrade before new content

**Decision:** Create new content only when verified demand, a distinct reader job, evidence depth, cluster role, and measurement plan exist. Upgrade or consolidate an existing page when it already serves substantially the same intent.

**Rationale:** Audits show duplicate intents and unmeasured content supply.

**Consequences:** Broad topic lists and content quotas are not backlog-ready problems. **Status:** Accepted.

## 2026-08-21 — Unknowns and assumptions

**Decision:** Label claims as Verified, Inferred, Unknown, or Recommended. Record the source, date/scope, and definition for metrics. A zero is not a substitute for missing access. Assumptions that change scope require a dated decision.

**Rationale:** Old operational artifacts presented placeholders as baselines.

**Consequences:** The scoreboard uses `Unknown` until an authorized export exists. **Status:** Accepted.

## 2026-08-21 — Completion proof

**Decision:** A ticket is complete only when its acceptance criteria, proof, relevant tests, production build, and user-facing visual check when applicable are recorded. Failures and skipped checks remain visible. Ticket/backlog/control docs are updated in the same change when behavior or assumptions change.

**Rationale:** Code presence, a merged PR, or an agent assertion is not outcome proof.

**Consequences:** Work without proof remains In Review or Blocked, never Done. **Status:** Accepted.

## 2026-08-21 — Bounded retries for generated-data file locks

**Decision:** Generated-data governance and citation writers may retry only transient Windows file-lock codes (`UNKNOWN`, `EBUSY`, `EPERM`, `EACCES`) with bounded exponential backoff. Capacity and semantic failures such as `ENOSPC` must fail immediately.

**Rationale:** The production build repeatedly failed on different ordinary JSON files under transient Windows locks; direct retries advanced and then completed the same deterministic pipeline.

**Alternatives considered:** Ignore/re-run indefinitely, disable scanning services, or rewrite the data pipeline. Rejected as unreliable, environment-invasive, or disproportionate.

**Consequences:** Local and CI data writes remain fail-closed for real errors while tolerating short file locks. **Status:** Accepted and validated.
