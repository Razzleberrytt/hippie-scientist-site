## 2026-08-21 — Backlog prioritization

**Decision:** Score eligible tickets as `(Business Impact × User Value × Traffic Potential × Strategic Leverage × Confidence) / Effort`. Impact/value/traffic/leverage and effort use 1–5; confidence uses 0.50, 0.75, or 1.00. Scores order comparable work but do not override dependencies or evidence/safety gates.

**Rationale:** The model is transparent, compact, and penalizes costly or weakly supported work.

**Alternatives considered:** Revenue-only ranking and an unscored task list. Both hide trust, user, dependency, or confidence costs.

**Consequences:** Any task that weakens safety, evidence, disclosure, or trust is ineligible regardless of score. **Status:** Accepted.

## 2026-08-28 — Generated data is written atomically by one shared helper

**Decision:** Every stage of the deploy data pipeline that writes JSON under `public/data` writes through `scripts/lib/atomic-json.mjs` (temp file → fsync → close → rename over target, with a direct-write fallback and bounded retry on transient sharing codes). Raw `fs.writeFileSync` into the generated data directory is rejected in CI by `scripts/ci/validate-atomic-data-writes.mjs`, wired into `npm run check`.

**Rationale:** `npm run build` rewrites the same ~1,800 generated files across nine consecutive stages, each re-opening files the previous stage closed milliseconds earlier. On Windows the antivirus/indexer handle on a freshly written file turns that re-open into a sharing violation that libuv cannot map to a POSIX errno, so it surfaced as `UNKNOWN: unknown error, open 'public\data\herbs-detail\berberis-aristata.json'`. The slug was incidental — only its position in directory enumeration. The failure was intermittent, and it had already been worked around twice: `postprocess-workbook-payloads.mjs` and `apply-governance-overlay.mjs` had each grown a private retry loop, while six other stages wrote raw and stayed exposed. A degraded primary build gate also meant `npx next build` became tribal knowledge, recorded as a standing workaround in `design-qa.md`.

Rename and truncating write fail under *opposite* lock shapes and neither dominates: rename requires the handle holder to have opened with `FILE_SHARE_DELETE`, a truncating write requires `FILE_SHARE_WRITE`. A scanner typically grants both; another Node process reading the file grants only the latter, where rename fails with `EPERM` though a plain write would have succeeded. Trying rename first and a direct write second covers both shapes; because the bytes are identical, the fallback costs only atomicity, never correctness.

**Alternatives considered:** Skip or `try`/`catch` the failing step (hides real failures and can ship truncated generated data); special-case the one slug (treats a symptom of enumeration order as a property of the data); leave each script with its own retry loop (already produced two divergent implementations and six gaps); rename-only without fallback (rejected after testing showed it regresses the reader-lock case).

**Consequences:** Generated JSON writes are crash-safe on the normal path — a target holds either the old bytes or the new bytes in full, never a partial write, which is what previously made recovery manual. New pipeline stages must be added to `GOVERNED_SCRIPTS` in the validator. Temp files are named `*.tmp`, which is gitignored and filtered out by every consumer's `.json` check, so a leaked temp is inert. The `design-qa.md` workaround note is removed.

**Verification:** `npm run build` passed before the change (37 steps, exit 0) and after (37 steps, exit 0) — the intermittent failure could not be forced to reproduce in this session, so this is a removal of the race, not a demonstrated repair of an observed break. Equivalence was measured instead: from an identical git-clean starting state with the build cache disabled, 1,806 of 1,807 files under `public/data` are byte-identical across the two builds. The one difference is `_meta/build-info.json`, whose only variable field is `generatedAt`; its `counts` derive from `herbs.json` and `compounds.json`, both byte-identical. Emitted output is unchanged: 1,368 HTML files and 1,311 Pagefind-indexed pages in both builds. Next's "Generating static pages (1379)" counter differs from the HTML file count by exactly the 11 route entries that emit non-HTML artifacts (`sitemap.ts`, `localized/sitemap.ts`, `robots.ts`, `feed.xml`, `rss.xml`, `updates/evidence-changes.xml`, `updates/recently-reviewed.xml`, `evidence/evidence-report/dataset.csv`, `evidence/evidence-report/dataset.json`, `opengraph-image.tsx`, `twitter-image.tsx`), each verified present in `out/`. **Status:** Accepted.

## 2026-08-29 — `src/` removed; `@/lib` and `@/components` each mean one thing

**Decision:** The `src/` tree no longer exists. Its 584 files were partitioned into 300 unreachable files, which were deleted, and 290 live ones, which moved to their root-level homes (`lib/`, `components/`, `types/`, `data/`, `generated/`, `content/drafts/`). The `@/*` alias resolves to exactly one location — the repository root — in `tsconfig.json` and in `vitest.config.ts`. `scripts/ci/validate-no-orphans.mjs`, wired into `npm run check`, keeps unreferenced files from accumulating again.

**Rationale:** Two parallel source trees cost something on every task. `CLAUDE.md` spent two sections explaining that `lib/` was active but `src/lib/` was legacy-except-for-some, and that `src/components/**` was legacy except for an enumerated handful. Every search returned matches from code that had not run in months, and duplicate implementations hid behind shared names.

**Counts before/after:** 584 src files → 0. Deleted 300 (269 non-test modules, 31 tests). Relocated 290. Root-level file count under `lib/` and `components/` is now 964. Tests went from 596 files / 2,888 assertions to 564 / 2,740 — a reduction of exactly the 32 deleted test files and their assertions, with every remaining test passing. Emitted pages unchanged.

**Where the supplied analysis was wrong, and why.** The starting analysis proposed deleting 414 files: 276 non-test plus 138 tests. Verification put the real number at 300, and the difference was not noise:

- **106 of the 138 tests were live.** The supplied model treated every test under `src/` as dead. In fact only a test whose *subject* — the module beside its `__tests__` directory — is itself dead can be deleted. Deleting all 138 would have removed coverage of live production code.
- **Five `src/types` modules were live**, including `researchEnrichment.ts` with eight importers. `src/types` was scoped for outright deletion; that would have broken the build.
- **Nine modules were reachable only by string paths no import scan sees.** `next.config.mjs` names `cloudflare-image-loader.ts` in a `loaderFile` field; `build-og-images.mjs` reaches `classMap.ts` through `import(path.resolve(...))`; report and verify scripts list `herb-data.ts`, `compound-data.ts` and `data.ts` as plain strings. No import statement mentions any of them.
- **One bug was in the verification tooling itself.** The first reachability pass skipped any directory named `ops` at any depth, which silently swallowed `components/ops/` and every root it contained. Cross-checking against a second method is what surfaced it.

Two detection methods were run — specifier resolution, and a path-precise textual reverse-reference scan — and iterated until they agreed on every file, ending at zero disagreements. Before any deletion, the dead set was verified *closed*: nothing outside it imported into it, so removing it whole leaves a consistent tree.

**Collisions found:** two, both genuine duplicates rather than naming accidents. `src/components/ui/Card.tsx`, a default-export `ds-card` wrapper, collided with an unrelated named-export family (`Card`, `DetailCard`, `EvidenceBadge`) and became `components/ui/SurfaceCard.tsx`. `src/lib/__tests__/evidence-grade.test.ts` collided with a root test of the same name but covers a different thing — the grade enum contract, versus the root file's coverage of `normalizeEvidenceGrade` / `reconcileEvidenceGrade` / `bandFromEvidenceTier` / `gradeTierDistance` — and became `evidence-grade-contract.test.ts`. Both were kept in full; evidence-grade semantics are not altered by a refactor.

**Consequences:** `vitest` previously resolved `@/*` src-first, the reverse of the tsconfig precedence, so while both trees existed a module present in each resolved to a *different file* under vitest than under `tsc` and `next`. That divergence is gone. 71 `src/` excludes left `tsconfig.json`; 21 were re-added at their new paths because those modules import helpers deleted long ago (`utils/calculateConfidence`, `utils/sanitizeData`, `types/enrichmentDiscovery`, `data/interactionTags.seed`) and cannot compile — repairing or removing them is separate work. Removing eslint's `src/**` block let the moved files pick up the `components/**` rules, which surfaced two genuinely unlabelled inputs in `compare/DynamicComparerClient.tsx`; both were fixed with `htmlFor`/`id`. `src/content` moved to `content/drafts/` rather than `content/`, because `content/blog` is a content-collections directory and moving a draft post there would have published it.

**Known follow-up, deliberately not done here:** 120 files under root `lib/` and `components/` are unreferenced and predate this work. They are recorded in `config/orphan-baseline.json` rather than deleted, because they were never put through the two-method verification used here and removing them is a second amputation that deserves its own scope. **Status:** Accepted.

## 2026-08-29 — Root-tree orphans removed; the no-orphans gate is now a strict zero-check

**Decision:** The 121 unreferenced files under `lib/` and `components/` recorded as a baseline by the `src/` amputation have been verified and deleted. `config/orphan-baseline.json` is empty, so `scripts/ci/validate-no-orphans.mjs` fails on *any* orphan rather than ratcheting against a tolerated set.

**Rationale:** The baseline was introduced because deleting 120 files that had never been through the two-method verification used on `src/` would have been an unscoped second amputation. Running that verification is what the baseline existed to defer, not to avoid. A tolerated set of 121 also weakens the gate: it only catches the 122nd.

**Verification:** The same procedure as the `src/` amputation. Method A resolves import specifiers, including quoted repo-relative string paths; Method B is a path-precise textual reverse-reference scan, blind in different places. The two disagreed on two files, both inspected and both confirmed dead: `components/seo/AnswerEngineTable.tsx` appears only in an eslint file list in `ai-entity-enrichment-check.yml` — an instruction to lint the file if present, not evidence of use — and `lib/content-linking.ts` appears only in a comment in `scripts/internal-linking-audit.mjs` saying that script *mirrors* its scoring, which it reimplements rather than imports. Before any deletion the dead set was confirmed **closed**: zero imports into it from outside.

**Counts:** 121 deleted (49 under `lib/`, 72 under `components/`), 9,224 lines. Files under `lib/` and `components/` went from 964 to 843. Tests unchanged at 569 files / 2,763 assertions, all passing. Build unchanged: 37 steps, 1,368 HTML files, 1,311 Pagefind-indexed pages.

**A regression in the `src/` amputation was found and fixed here.** That work swept `scripts/` for `src/` references but not `.github/`, which held 56 across 12 workflows. Most were stale `paths:` triggers, harmless but misleading. One was not: `ai-entity-enrichment-check.yml` passed seven deleted `src/` files directly to `eslint`, and would have failed on `main`. Every explicit path in every workflow now resolves, all 55 workflows parse, and that eslint invocation runs clean. `tests/heavy-pr-workflow-scope-contract.test.ts`, which pinned `- 'src/**'` in those path lists, now pins `types/**`.

**Consequences:** `lib/` and `components/` contain only reachable code, and the gate holds that at zero rather than at a number. The check that guards this is itself the thing most likely to drift, so its resolver — not the baseline — is where new reference mechanisms must be taught. **Status:** Accepted.
